# StockPilot｜營運與 KOL 分析 PRD

這是一份工作中用來對齊營運流程、開發需求與驗收條件的產品需求文件。以現有訂單、銷售與 KOL 模組為基礎，重點回答：訂單歸給誰、這位 KOL 帶來哪些商品銷售，以及數字能否回查原單。

## 1. 問題與使用者價值

營運人員需要反覆整理不同來源的訂單，才能回答銷售與合作問題。若商品代碼、UTM 或訂單狀態沒有一致規則，同一份報表容易出現重複計算、錯誤歸屬，以及無法追溯的數字。

本系統讓營運人員先核對資料再入帳，讓行銷人員從 KOL 檔案進入商品與訂單明細，支持後續選品與合作討論。

**主要使用者故事：** 身為營運／行銷人員，我希望打開某位 KOL 的檔案，就能看到合作資訊、有效訂單與商品件數，再回查來源訂單，判斷過去合作賣了哪些商品。

歷史商品表現是選品的參考，不代表未來銷量預測，也不直接證明合作造成的增量銷售。

## 2. 範圍與資料邊界

| 模組 | 本次範圍 |
| --- | --- |
| 訂單接收 | 建立來源與商品對照、手動接單、標準 CSV／指定格式 Excel 預檢與確認 |
| 銷售分析 | 有效訂單的商品金額、件數、趨勢、明細與 CSV 匯出 |
| KOL 歸檔 | 夥伴資料、合作開始時間、活動名稱與多組 UTM medium 設定 |
| KOL 匯入 | 單份訂單 Excel 預覽、確認、更新、排除與操作恢復 |
| KOL 分析 | 依歸屬查看有效訂單、訂單金額、商品數量、來源明細與匯出 |

營運與倉管資料各自獨立，不同步訂單、不建立出貨單、不扣庫存。KOL Excel 分析資料不會改寫一般營運訂單或商品庫。

ROAS、廣告費、分潤結算、獲利及未來銷量預測不在目前模組範圍內。AI 問答屬獨立唯讀功能，不是完成本篇流程的必要條件。

## 3. 一般訂單與銷售流程

| 步驟 | 操作 | 結果 |
| --- | --- | --- |
| 1. 準備 | 建立營運端 SKU 與訂單來源 | 手動及標準 CSV 的商品能對應本系統資料 |
| 2. 接單 | 手動新增訂單，或上傳檔案預檢 | 手動保存後可查單；檔案預檢顯示錯誤、缺漏與新增項目 |
| 3. 確認 | 核對檔案預覽後確認匯入 | 訂單正式保存；預覽本身不計入銷售 |
| 4. 查詢 | 設定期間、來源與商品 | 查看有效訂單的商品銷售、數量及明細，並匯出 CSV |
| 5. 更正 | 核對訂單修訂或取消結果 | 保留紀錄；取消單不計入有效銷售 |

指定格式 Excel 可依預覽建立新 SKU，但不增加庫存。標準 CSV 使用既有商品對照；非庫存明細另行標示。檔案限 2 MB、最多 5,000 筆資料列；目前使用 TWD，未帶時區的 Excel 日期按台北時間解讀。

## 4. KOL 核心操作流程

### 4.1 建立夥伴檔案

填寫 KOL 名稱、合作開始時間與至少一組 UTM medium；可補平台、活動名稱及備註。一位 KOL 可對應多組 UTM，同一個已保存的 UTM 代碼不能同時屬於兩位 KOL。

歸屬依 UTM medium 與合作開始時間計算，不以姓名、平台名稱或人工 KOL 備註猜測。

### 4.2 匯入訂單並核對

| 步驟 | 使用者操作 | 系統回應 |
| --- | --- | --- |
| 1. 選擇來源 | 選已建立的訂單來源與訂單 Excel | 預設直接使用檔案內 SKU、商品名稱與選填類型，不需第二份商品對照檔 |
| 2. 預覽 | 核對原始列、商品、數量、訂單金額與 UTM | 顯示新增、更新、相同略過、排除、錯誤及未知 UTM |
| 3. 修正 | 錯誤資料修正後重新上傳 | 有阻擋錯誤時不可確認；未知 UTM 可以保留待確認歸屬，不必猜測 |
| 4. 確認 | 確認採用本批資料 | 以來源＋訂單號辨識，更新該訂單完整內容；保留舊批次供追查 |
| 5. 恢復 | 送出結果不明時查原操作與批次 | 確認是否已保存，不以換檔名重送來判斷成功 |

有效訂單缺 SKU、名稱、必要金額，或同 SKU 名稱／類型矛盾時阻擋確認。取消單可保留取消紀錄；商品類型未填時為未分類。

**舊格式相容模式：** 僅在另行設定商品對照表時使用。此模式才執行 `+` 拆項、`*N` 倍數、歷史代碼修正及商品對照排除；一般單檔模式保留原 SKU，不自動拆解。舊模式的內部訂單標記預設排除於統計，可選擇包含；不能將此判定套用所有新格式。

### 4.3 核對訂單歸屬

| 條件 | 分類 | 後續處理 |
| --- | --- | --- |
| 沒有 UTM medium | 一般訂單 | 保留供核對，不當成 KOL 成效 |
| 有 UTM，但未精確匹配 | 待確認歸屬 | 查來源後補正 KOL 的 UTM 設定 |
| UTM 匹配，但下單早於合作開始 | 待確認歸屬 | 核對合作時間與訂單日期 |
| UTM 匹配，且下單不早於合作開始 | 對應 KOL | 計入該夥伴的有效訂單分析 |

每筆訂單只有一個歸屬分類。一般訂單與待確認歸屬是固定分類，不是 KOL，不能修改或刪除。

UTM 以去除前後空白後的字串精確比對。設定預設轉小寫，可選保留大小寫；來源訂單不自動轉小寫，所以 `sunny` 與 `Sunny` 可能不同。

新增、修改或刪除 KOL 設定後，報表依目前設定重新計算，不必重新匯入訂單。歷史期間數字也可能隨設定改變，因此需保留查詢條件與設定版本。

### 4.4 查看這位 KOL 賣了什麼

1. 從 KOL 名單或統計進入夥伴專屬頁，核對活動、平台、合作時間及 UTM。
2. 選定下單期間與來源，查看有效訂單數、訂單總金額及平均訂單金額。
3. 進入商品統計，查看 SKU、商品名稱、購買件數與包含該商品的有效訂單數。
4. 點選商品的訂單列表，確認哪些訂單包含該商品；必要時進入訂單詳情及來源批次。
5. 查看一般訂單與待確認歸屬，避免把資料缺漏誤認成某位 KOL 的低成效。

KOL Excel 商品只有清洗後數量與完整訂單金額，**不把整張訂單金額分攤成各商品營收**。選品討論可依商品件數與訂單數進行，不能用不存在的商品營收排名代替。

## 5. 計算口徑

| 項目 | 定義 |
| --- | --- |
| 日期 | 依台北下單日期，含起訖日；不代表實際出貨日期 |
| 一般銷售金額 | 有效訂單商品折後明細金額，不含另列稅與運費；套組收入留在套組 |
| KOL 有效訂單數 | 選定範圍內有效訂單，依來源＋訂單號去重 |
| KOL 訂單總金額 | 每筆有效訂單完整金額只計一次；不因商品拆行重複相加 |
| 平均訂單金額 | 完整有效訂單金額／有效訂單數；有缺值時不能當零計算 |
| 商品件數 | 有效訂單中該商品數量合計；商品訂單數是包含該商品的訂單數 |
| 缺少金額 | 顯示缺值筆數與已知金額；總額及平均值不假裝完整。新 Excel 的必要金額缺漏會在預覽阻擋 |
| 取消／清洗排除 | 可在明細查閱，但不計入有效業績 |
| 重複資料來源 | 同來源同訂單同時存在一般訂單與 KOL 匯入時，KOL 報表優先採 KOL 匯入版本；不改寫一般銷售資料 |
| 篩選範圍 | 期間、來源、KOL 與平台限制整體分析；狀態、UTM、商品的明細篩選不等同重算整體有效業績 |

一般銷售與 KOL 報表可能採不同資料版本及金額口徑，不可直接相加。平台篩選依 KOL 設定的平台判斷，需與訂單來源平台區分。

## 6. 核心需求與驗收

以下為驗收標準，並非本次執行紀錄。所有案例使用合成資料。

| 編號 | 需求與價值 | 驗收條件 |
| --- | --- | --- |
| OP-R01 | 預檢與入帳分開，避免錯誤資料進入銷售 | 預覽一筆訂單時銷售不增加；確認後只增加一次；錯誤批次不可確認 |
| OP-R02 | 銷售可回查訂單 | 有效商品金額 800 元、取消訂單 500 元，同期間有效銷售為 800 元；明細可找到來源與單號 |
| OP-R03 | KOL 設定唯一且避免覆寫 | A 已使用 `sunny`，B 再使用同碼時阻擋；以過期設定版本保存或刪除時提示重新讀取 |
| OP-R04 | 單份 Excel 可完成匯入 | 未設定商品對照表時，合法訂單檔可預覽並確認；SKU 中的 `+`、`*` 保留原字串 |
| OP-R05 | 三種歸屬完整且互斥 | 五筆有效訂單含兩筆符合 KOL、一筆空 UTM、一筆未知 UTM、一筆早於合作時間：分別為 2／1／2 筆，合計五筆 |
| OP-R06 | 補 UTM 後可重新歸檔 | 將未知 UTM 加入正確 KOL 且合作時間涵蓋訂單；原訂單移入該 KOL，待確認減一，不重匯、不增訂單 |
| OP-R07 | KOL 可查看商品與來源訂單 | A 的兩張單分別為杯子兩件、杯子一件加袋子一件：杯子三件／兩單，袋子一件／一單；點商品只列相關單 |
| OP-R08 | 訂單金額不因商品拆行膨脹 | 一單兩個商品，訂單合計 1,000 元，KOL 合計仍為 1,000 元；Excel 商品明細不展示捏造的營收分攤 |
| OP-R09 | 重複與更新可追溯 | 同一批重複確認只計一次；同來源訂單由有效更新為取消後，有效業績移除，舊批次可查；舊預覽不得覆蓋新版本 |
| OP-R10 | 結果不明可恢復 | 模擬預覽／確認回應遺失，查原操作與批次取得結果；不得新增重複訂單 |
| OP-R11 | 查閱分析不改動業務資料 | 切換篩選、查看商品與匯出後，一般訂單、庫存及 KOL 匯入訂單內容不變 |

## 7. 成效觀測

| 指標 | 衡量方式 |
| --- | --- |
| 合作報表整理時間 | 相同資料量下，從選檔到產出可核對分析的時間；另記錄修正錯誤時間 |
| 歸屬待確認比例 | 同一範圍有效待確認訂單數／全部有效訂單數；一般訂單另列，不預設為錯誤 |
| 商品追查完成率 | 能從指定 KOL 找到商品件數並回查原訂單的成功任務數／受測任務數 |
| 資料一致性 | 去重、取消、重新歸屬後，分類加總、訂單與商品明細是否符合定義 |

基準、目標值與觀測期間待實測確認；現階段不把過往工作成果當成此開源系統的實測成效。

## 8. 限制與待確認事項

- 歷史歸屬依目前 KOL 設定重算；不可變的活動結案快照與歷史分潤版本尚未列入現有能力。
- 舊格式的商品修正與內部訂單規則有特定使用背景；不同商家採用前需核對適用性。
- 多人權限、完整備份還原、設備與大量資料效能需另行驗收。
- 商品收入分攤、合作費用、ROAS 與分潤若要擴充，需先定義資料來源及計算規則。
- Demo 使用獨立合成資料展示歸屬、商品與訂單追查，不等同完整 Excel 匯入或正式營運環境。
