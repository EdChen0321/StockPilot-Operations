# 訂單與銷售指南

[回到專案首頁](../README.md) · [KOL 分析指南](kol-analysis.md)

## 使用目標

這份指南帶營運人員在本系統建立商品對照與來源，接收或匯入訂單，再核對銷售總覽和明細。營運系統不會向倉管系統傳送訂單，也不會扣除其庫存。

## 前置條件

- 手動訂單與標準 CSV 中的庫存商品，需要先在本系統「SKU 商品庫」建立對照；這份商品庫與倉管系統分開。
- 手動訂單與標準 CSV 需要訂單來源，可從「訂單來源管理」建立。
- 匯入前保留原始檔，確認來源、幣別與日期。預檢本身不會將訂單計入銷售。

## 操作流程

```text
建立本系統 SKU 與來源 → 手動接單或選擇檔案 → 預檢並確認 → 核對訂單 → 查詢銷售
```

### 1. 手動接收訂單（Step 1）

進入「訂單接收 → 接收訂單」，按「新增訂單」。選擇來源與下單時間，加入商品 SKU、數量與金額；若明細不是庫存商品，可選「新增非庫存明細」。顧客識別碼、KOL 標記、UTM medium 及訂單總金額可依實際來源填寫，未知值留白。

保存後回到訂單列表，用來源、狀態或商品搜尋原單。取消訂單會保留修訂紀錄，但該單不再計入有效銷售。本系統不提供由訂單直接建立倉管出貨單的入口。

### 2. 匯入 Excel 或標準 CSV

在「資料匯入 → 匯入銷售訂單」選擇檔案，確認這份檔案是否代表要採用的完整訂單明細，再按「上傳並預檢」。先閱讀批次預覽中的錯誤、缺漏與將建立的商品；只有核對完成後，才按畫面上的確認匯入按鈕。

| 檔案 | 目前要求 |
| --- | --- |
| 指定格式 Excel | `.xlsx`、單一可見工作表、儲存格為值；必要欄位包含訂單號碼、日期、狀態、貨幣、合計、商品貨號、名稱、結帳價與數量 |
| 標準 CSV | UTF-8 `orders-v1`；必填欄位見匯入頁，庫存明細的 `external_sku` 必須能對到本系統 SKU |

目前貨幣限 TWD；Excel 未帶時區的日期按台北時間。來源標示為「已完成」不代表本系統已完成出貨。Excel 可在確認後建立預覽列出的新 SKU，但不會增加庫存。檔案限制為 2 MB、最多 5,000 筆明細；標準 CSV 的非庫存明細使用 `line_type=non_stock` 並留空 `external_sku`。

若送出後結果不明，先查「匯入紀錄」與原訂單，確認是否已保存或確認，再決定是否重試。不要改檔名重送同一批資料來猜測結果。

### 3. 查詢銷售

「銷售總覽」依**下單日期**顯示商品銷售金額、有效訂單數、品項數量與趨勢。到「銷售查詢」可依期間、來源與品項縮小範圍，查看明細或匯出目前篩選的 CSV。日期含起訖日，依台北時區計算。

商品金額是訂單商品的折後金額，不含另列的稅與運費；取消訂單不計入有效銷售。套組收入留在套組，不分攤到組成商品。報表不代表倉管端的實際出貨量。

## 完成後驗證

- 來源、訂單編號、下單時間與商品明細可回到原始紀錄核對。
- 預檢有錯誤時未入帳；確認後在訂單列表與匯入紀錄能找到同一批次。
- 銷售總覽與銷售查詢使用相同期間及口徑時，金額與訂單數一致。
- 取消或重複匯入沒有讓有效訂單與商品金額重複計算。

## 常見問題與排錯

| 狀況 | 先核對 |
| --- | --- |
| CSV 的 SKU 無法對應 | 是否先在本系統建立同一個 SKU；營運與倉管的商品庫不共用 |
| 預檢有錯誤 | 依預覽指出的欄位及列數修正原始檔，再重新預檢；尚未確認前不會入帳 |
| 銷售金額與訂單合計不同 | 銷售查詢使用商品折後金額，不含另列稅與運費；另核對取消狀態 |
| 送出後結果不明 | 先查匯入紀錄與訂單列表，確認原批次結果後再決定是否重試 |
